## R3-T1 — CPU unit and memory meaning
Decision taken: per-process and per-group CPU is a share of the whole PC (÷ logical CPUs), memory in rows is private memory (resident − shared). Both were in the run prompt. A group's total is the sum of private memory, so it can differ from what `top` shows per process (RSS); the details line shows RSS and "x % of one core". Recommended: keep. Open: kernel threads still show as rows (0 MB); say if they should be hidden.

## R3-T2 — process data comes from `/proc` directly
`core::procfs` replaces sysinfo's process refresh (32 ms/tick). It assumes USER_HZ = 100 (true on Linux for user space) and reads the page size from `/proc/self/smaps`. Recommended: keep. Per-process CPU is 0 for the first second after opening Performance or Processes (no earlier reading to compare with); say if that blank second matters.

## Run 07 — R7-Q03 dpkg / rpm owner lookups: decisions taken without you
1. **`rpm -qf` is run once per launcher file** (`/usr/bin/rpm -qf --qf '%{NAME}\n' /usr/share/applications/x.desktop`), not once for all files, because a multi-file run does not say which name belongs to which file (and a file with two owners prints two lines). On a Fedora machine with about 300 launchers that is about 300 short runs on the Apps worker thread; not measured (no rpm here). Alternative: one run with `--qf '%{NAME}\t%{FILENAMES}…'`, which needs a real rpm to get right. Recommended: keep, measure on a Fedora container, switch if it is slow.
2. **No `--` before the file in `rpm -qf`:** every file is absolute (`/…`) so none can look like an option, and I am not sure rpm's option parser accepts `--` there; `dpkg -S` gets `--` (documented). Recommended: confirm on a real rpm.
3. **`dpkg -S` exit code is ignored** (it exits 1 when any file is unknown but still prints the found ones); `rpm -qf` exit code too. A parse that finds nothing is the same as "no apps" for that machine, silently. Recommended: show "Tidewise could not tell which packages are apps" if the runner itself fails (not built).
4. **All fixtures are hand-written** (`tests/fixtures/desktop-owners/rpm-qf-*-handwritten.txt`; the dpkg one already was): this machine has `dpkg` but no apt database, and no `rpm`. The exact wording of rpm's "not owned" sentence is from memory; a different wording is skipped anyway (only plain package names are accepted), so the failure mode is "fewer apps", not a wrong app. Rows stay `Needs Verification`.
5. **Multi-arch dpkg owners** (`libc6:amd64`) are matched against the package id as `AptApps` lists it (`${Package}`, no arch), so a multi-arch app would not match. Launchers of multi-arch packages are rare; not handled. Recommended: check on a real Ubuntu.
6. **Apt and dnf now count in the Apps list on a machine that has their tools.** On this Arch machine nothing changed: live Apps still lists the same sources (see report). Also added `fresh_plan` arms for apt and dnf (so the confirm re-check works for them).
