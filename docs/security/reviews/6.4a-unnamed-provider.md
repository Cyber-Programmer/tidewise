## Found while building (not by the reviewer)

- The approved plan said a named package is always the one pacman uses. Real pacman disproves it for a version that
  does not fit, so the helper also requires other providers of an answered name to come with the named package.
- An installed package named as a provider **is** in the dry run (a reinstall), so "the chosen package must be listed"
  does not refuse it. Measured: `an_installed_package_named_in_a_dry_run_is_listed_again`. The helper accepts it, as it
  did before (`a_provider_the_user_already_installed_by_hand_stays_explicit`). The resolver could send such an answer
  when the user installed the provider between two rounds; that is fixed and tested.
