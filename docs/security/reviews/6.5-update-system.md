# Adversarial review: 6.5, Update system (26 Nov 2026)

Scope: `git diff main..ea21710` on `feat/6.5-update-system`, by a fresh subagent, against the threat model and decision
0009, covering every pacman command the helper runs in an update. Reproductions ran the real helper in throwaway
rootless containers (`--network=none`) with extra dummy repositories; the scripts were scratch files and are not kept.
**Updated 27 Nov 2026:** R-01 and R-02 were changed (the human's decisions) and reviewed again below. The second review's S-01, S-02 and S-06 are closed by blocking
replacements; S-03 and S-04 are accepted limits.

"Verified" = the main session re-ran the reproduction itself.

| id | severity | finding | evidence | status |
|---|---|---|---|---|
| R-01 | **High** | **A declined replacement can still upgrade the old package, with new dependencies nobody confirmed.** Installed `old 1.0`; the repository has `old 2.0` and `new` with `replaces=(old)`. The helper answers `ok`; the post-check only counts confirmed packages that are missing. Breaks golden rules 5 and 10. The app shows the same wrong list. Found sound (mostly from reading): argument injection (values after `--`, allow-listed again, the `-Ss` pattern anchored
and escaped); exit codes, truncation, timeouts and parse failures of the new reads refuse; every provider-check refusal

conflicts and skips, no way found to **remove** a package; `check_providers` for installs behaves as before.

Not checked: groups, signed repositories, a change of the local database between the check and the real run, an
already-installed replacer, the window itself.

## Third, short review (27 Nov 2026): the replacement block

Scope: `git diff 0807d2a..fb75f9b` (helper and shared rule), by a fresh subagent, real helper in throwaway containers.
S-01 and S-02 are closed. Randomised runs of generated repositories found no accepted unlisted change (weak evidence:
they did not hit T-01 either).

| id | severity | finding | evidence | status |
|---|---|---|---|---|
| T-01 | Medium | **A self-replacement gets through.** The rule skips a `Replaces` entry naming the package itself. A repository package that replaces its own name, is **not newer** than the installed copy and provides something new is listed by `--print` and satisfies another upgrade's need; the real run declines it and installs other packages for that need. The helper answers `ok`; the app shows no warning. Contrived, but self-replacers exist (`python-pylint-pydantic`, `python-pylint-plugin-utils`). | Reproduced; verified by the main session (two unlisted packages installed). | **Closed** (the human, 27 Nov): no self-replacement exemption. Container `a_package_that_replaces_its_own_name_is_refused`, red before the fix. Cost: such a package is listed by every `-Su`, so every update is blocked while it is installed (measured). |
| T-02 | Low | False refusals: `IgnorePkg` on the replaced package, or a replacer from a later repository, makes pacman ask nothing, yet app and helper block. | Reproduced by the reviewer. | **Accepted as a limit** (the human, 27 Nov): errs on the safe side. |

Notes from reading: the resolver (installs) has no replacement block, so WBS 6.6 must add it for "update and install"
or the app will show Ready where the helper refuses; the check runs once, before the lists move; `-Si` now runs on every
update (4 MiB cap, about 5000 packages).
