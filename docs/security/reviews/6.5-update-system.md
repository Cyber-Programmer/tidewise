# Adversarial review: 6.5, Update system (26 Nov 2026)

Scope: `git diff main..ea21710` on `feat/6.5-update-system`, by a fresh subagent, against the threat model and decision
0009, covering every pacman command the helper runs in an update. Reproductions ran the real helper in throwaway
rootless containers (`--network=none`) with extra dummy repositories; the scripts were scratch files and are not kept.
**Updated 27 Nov 2026:** R-01 and R-02 were changed (the human's decisions) and reviewed again below. **Release blockers
open: S-01, S-02** (R-01 is only partly closed).

"Verified" = the main session re-ran the reproduction itself.

| id | severity | finding | evidence | status |
|---|---|---|---|---|
| R-01 | **High** | **A declined replacement can still upgrade the old package, with new dependencies nobody confirmed.** Installed `old 1.0`; the repository has `old 2.0` and `new` with `replaces=(old)`. The helper answers `ok`; the post-check only counts confirmed packages that are missing. Breaks golden rules 5 and 10. The app shows the same wrong list. Present in the helper before this branch. `-Su --print --ask 66` prints the same. | Reproduced (reviewer: three setups; verified: `old` upgraded, an unlisted provider installed). In each, `-Qu` on the private copy names `old` and the dry run does not. | **Partly closed 27 Nov, see S-01 and S-02** (`3a68d12`): `--ask 66` does not change the dry run, so the helper compares `-Qu` on the private copy and refuses; the app blocks the same case. Red `an_upgrade_the_list_does_not_name_refuses_before_anything_moves` and the container test against the old helper. Not done: a notice for packages changed that were not confirmed. |
| R-02 | **High** | **Soname dependencies (`libx.so=1-64`) are skipped by the provider rule**, so two providers of a soname are chosen by pacman unasked. Found sound (mostly from reading): argument injection (values after `--`, allow-listed again, the `-Ss` pattern anchored
and escaped); exit codes, truncation, timeouts and parse failures of the new reads refuse; every provider-check refusal
comes before the move, so the real lists are untouched; the new reads take no database lock; `--ask 66` declines
conflicts and skips, no way found to **remove** a package; `check_providers` for installs behaves as before.

Not checked: groups, signed repositories, a change of the local database between the check and the real run, an
already-installed replacer, the window itself.

## Second review (27 Nov 2026)

Scope: `git diff 061f91b..0ba2acd`, by a fresh subagent, with the real helper in throwaway rootless containers
(`--network=none`, its own dummy repositories).

| id | severity | finding | evidence | status |
|---|---|---|---|---|
| S-01 | **High** | A declined replacement still installs unlisted packages: an upgrade needs a name the replacer provides, and a package is literally called that. The dry run lists the replacer and the upgrade; `-Qu` names only the upgrade; the "lone provider" rule ignores the literal package. The real run declines the replacement and installs the literal package and its dependencies; the helper answers `ok`; the app shows no warning. | Reproduced; verified by the main session (two unlisted packages installed). | **Open, for the human.** Proposed: a second private dry run with `--ignore <replacers>`; every line must be on the confirmed list (new command). Narrower: count a literal package of that name in the lone rule. |
| S-02 | Medium | `-Qu` is blind when an earlier repository has `Usage` without `Upgrade`: the replaced package is still upgraded. | Reproduced; verified. | **Open**, same fix as S-01. |
| S-03 | Low | A soname need spelled differently from the `Provides` (`>=`, or without the release part) is never judged. No such need found in the official repositories. | Reproduced by the reviewer. | **Open, for the human.** Match as pacman does; count every provider for a non-`=` rule. |
| S-04 | Low | False refusal: a needer that names the provider before the soname gets no question from pacman, but is refused (real: `dovecot`, `postfix-mysql` and others with `mariadb-libs`). | Reproduced by the reviewer. | **Open, for the human.** Skip such a pick. |
| S-05 | Note | The intended refusal reaches far: about 1178 of 15784 packages have `libjack.so` in their closure (approximate), `ffmpeg`, `firefox`, `mpv` among them. On a system with neither `jack2` nor `pipewire-jack`, all are refused. | Estimated from sync data. | **For the human.** The card could say that installing `pipewire-jack` in a terminal first lets Tidewise continue. |
| S-06 | Low | The `-Qu` check blocks every update when only a package's NEW version is in an `IgnoreGroup`. | Reproduced; verified (refused as `transaction_changed`). | **Open**; the S-01 fix could replace the `-Qu` comparison. |

Notes from reading: `-Qu` is not repeated after the lists move (a narrow window); the helper's stricter repository-name
rule on search results can make app and helper disagree (fails closed); the `checking` event is often sent twice
(harmless).

Found sound: the `checking` event; the refusal comes before the move; batched search names allow-listed and escaped,
batches small, read errors refuse; no new way to remove a package.

Not checked: R-05, R-06, signed repositories, very large `-Si` output, the window, a local database changing mid-job.
