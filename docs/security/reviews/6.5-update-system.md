# Adversarial review: 6.5, Update system (26 Nov 2026)

Scope: `git diff main..ea21710` on `feat/6.5-update-system`, by a fresh subagent, against the threat model and decision
0009, covering every pacman command the helper runs in an update. Reproductions ran the real helper in throwaway
rootless containers (`--network=none`) with extra dummy repositories; the scripts were scratch files and are not kept.

"Verified" = the main session re-ran the reproduction itself. **Release blockers are open: R-01, R-02.**

| id | severity | finding | evidence | status |
|---|---|---|---|---|
| R-01 | **High** | **A declined replacement can still upgrade the old package, with new dependencies nobody confirmed.** Installed `old 1.0`; the repository has `old 2.0` and `new` with `replaces=(old)`. The dry run lists only `new`. The real run (`--ask 66`) declines the replacement and then upgrades `old` to 2.0 and installs what it needs. The helper answers `ok`; the post-check only counts confirmed packages that are missing. Breaks golden rules 5 and 10. The app shows the same wrong list. Present in the helper before this branch. `-Su --print --ask 66` prints the same. | Reproduced (reviewer: three setups; verified: `old` upgraded, an unlisted provider installed). In each, `-Qu` on the private copy names `old` and the dry run does not. | **Open, for the human.** Suggested: the helper runs `-Qu --dbpath /run/tidewise-helper-lists/` before the move and refuses if a non-`[ignored]` name is not in the dry run (a new command: approval needed); the app blocks the same condition from its own `-Qu`. Also report packages changed that were not confirmed. |
| R-02 | **High** | **Soname dependencies (`libx.so=1-64`) are skipped by the provider rule**, so two providers of a soname are chosen by pacman unasked. Also true of installs, and older than this branch. | Reproduced and verified. | **Open, for the human.** Suggested: judge sonames too, counting only providers whose `Provides` version is equal (otherwise `lib32` packages cause false refusals). Whether installs change is a decision. |
| R-03 | Medium | A versioned need passed through an installed provider that was too old, while `-T` was satisfied by one about to drop the name. | Reproduced and verified. | **Fixed** (`1aefc24`): a versioned need never passes that way. Red `a_versioned_need_never_passes_through_an_installed_provider`. Refused by the real helper after the fix. |
| R-04 | Medium | An upgraded provider that drops the name was hidden by a same-named package of another repository. | Reproduced and verified. | **Fixed** (`1aefc24`): the listed record decides. Red `an_upgraded_provider_whose_new_version_drops_the_name_does_not_stay`. Refused after the fix. |
| R-05 | Medium | `update_system_and_install` has no provider check, so a caller can avoid the new one with it. Older than this branch (threat model 40). R-01 applies to it too. | Read. | **Open, for the human** (WBS 6.6, or refuse the action until then). |
| R-06 | Low | A repository whose `Usage` lacks `Search` is invisible to `-Ss`, so a provider can look lone while pacman asks. | Reproduced by the reviewer only. | **Open, for the human** (needs a `pacman-conf` read, or record as a limit). |
| R-07 | Low | One name in two repositories counted as one provider; pacman asks between them. | Reproduced and verified. | **Fixed** (`1aefc24`). Red `the_same_name_in_two_repositories_is_a_choice`. Refused after the fix. |
| R-08 | Note | New commands missing from the bad-name, empty-list and time-limit tables. | Read. | **Fixed** (test only). |

Found sound (mostly from reading): argument injection (values after `--`, allow-listed again, the `-Ss` pattern anchored
and escaped); exit codes, truncation, timeouts and parse failures of the new reads refuse; every provider-check refusal
comes before the move, so the real lists are untouched; the new reads take no database lock; `--ask 66` declines
conflicts and skips, no way found to **remove** a package; `check_providers` for installs behaves as before.

Not checked: groups, signed repositories, a change of the local database between the check and the real run, an
already-installed replacer, the window itself.
